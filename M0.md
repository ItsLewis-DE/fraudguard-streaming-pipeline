## 2. Definition of Done

M0 hoàn thành khi:

```bash
uv sync --group dev
uv build
uv run fraudguard --help

uv run pytest -m smoke
uv run ruff check .
uv run ruff format --check .

uv run pre-commit run --all-files
```

Tất cả command trên không cần Kafka, ClickHouse, MinIO, Spark, Airflow, MLflow,
Ollama hoặc Internet ở runtime.

Smoke command phải:

- import được installed package;
- đọc và validate YAML thành Pydantic model;
- từ chối unknown/missing/invalid fields;
- ghi nhận CPU, RAM, GPU availability và random seed;
- in JSON hợp lệ khi dùng `--json`;
- không mutate repository;
- exit `0` nếu pass, non-zero nếu config/runtime self-check fail.

## 4. Bước 1 — Chuyển project thành installable package

### 4.1 Vì sao phải có build system?

Hiện tại `uv` chỉ cài dependencies, không cài source của FraudGuard. Nếu dùng
`src` layout và CLI entry point, project phải khai báo build backend để
`uv sync` cài package editable.

M0 dùng `setuptools` vì:

- hỗ trợ custom source root `ml/src` rõ ràng;
- ổn định và không cần biến repository thành uv workspace;
- tránh tạo một `pyproject.toml` thứ hai trong `ml/`.

Không tạo nested virtual environment hoặc nested lockfile.

### 4.2 Thay đổi `pyproject.toml`

Giữ dependency hiện tại và thêm các phần sau. Khi implement, dùng `uv add` để
chọn version tương thích và cập nhật `uv.lock`; không sửa lockfile bằng tay.

## 5. Bước 2 — Typed Pydantic configuration

### 5.1 Contract

YAML chỉ là serialization format. Sau khi parse bằng `yaml.safe_load`, dữ liệu
phải được validate ngay bằng Pydantic trước khi được trả về application code.

Application code không được:

- gọi `yaml.load` không có safe loader;
- truyền dictionary YAML thô qua nhiều layer;
- dùng `.get("field", default)` rải rác;
- âm thầm bỏ qua unknown field;
- nhận string `"8"` cho một integer nếu config yêu cầu strict type;
- mutate config trong training run.

### 5.2 Models ban đầu

`ml/src/fraudguard_ml/config.py`:

```python
from __future__ import annotations

from pathlib import Path
from typing import Literal, TypeVar

import yaml
from pydantic import BaseModel, ConfigDict, Field, PositiveFloat, PositiveInt


class StrictModel(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        frozen=True,
        strict=True,
    )


class RuntimeConfig(StrictModel):
    random_seed: int = Field(42, ge=0, le=4_294_967_295)
    max_cpu_threads: PositiveInt = 8
    memory_limit_gib: PositiveFloat = 6.0
    require_gpu: bool = False


class SmokeConfig(StrictModel):
    schema_version: Literal[1] = 1
    project_name: Literal["fraudguard"] = "fraudguard"
    runtime: RuntimeConfig


ConfigT = TypeVar("ConfigT", bound=BaseModel)


def load_yaml_config(path: Path, model_type: type[ConfigT]) -> ConfigT:
    try:
        raw_text = path.read_text(encoding="utf-8")
    except OSError as exc:
        raise ValueError(f"Cannot read config file: {path}") from exc

    try:
        raw_data = yaml.safe_load(raw_text)
    except yaml.YAMLError as exc:
        raise ValueError(f"Invalid YAML syntax: {path}") from exc

    if not isinstance(raw_data, dict):
        raise ValueError(
            f"Config root must be a mapping, got "
            f"{type(raw_data).__name__}: {path}"
        )

    return model_type.model_validate(raw_data)
```

Điểm quan trọng:

- `extra="forbid"` phát hiện typo như `random_sead`.
- `frozen=True` ngăn config bị đổi giữa run.
- `strict=True` tránh coercion âm thầm.
- `Literal[1]` tạo điểm kiểm soát schema evolution.
- `safe_load` ngăn YAML dựng arbitrary Python object.
- Dictionary chỉ tồn tại cục bộ trong loader và được chuyển ngay thành model.

Không dùng `BaseSettings` ở bước này. Training config là versioned YAML; secret
và connection settings mới thuộc environment variables ở milestone cần I/O.

### 5.3 Smoke config

`configs/smoke.yaml`:

```yaml
schema_version: 1
project_name: fraudguard
runtime:
  random_seed: 42
  max_cpu_threads: 8
  memory_limit_gib: 6.0
  require_gpu: false
```

`memory_limit_gib` là policy limit của training run, không phải tuyên bố máy có
đúng lượng RAM đó. Runtime metadata phải ghi cả configured limit và detected
host memory.

## 6. Bước 3 — Reproducibility contract

### 6.1 Seed helper

`ml/src/fraudguard_ml/reproducibility.py`:

```python
from __future__ import annotations

import importlib.util
import os
import random
from typing import Any


def configure_thread_limits(max_cpu_threads: int) -> None:
    value = str(max_cpu_threads)
    for variable in (
        "OMP_NUM_THREADS",
        "OPENBLAS_NUM_THREADS",
        "MKL_NUM_THREADS",
        "NUMEXPR_NUM_THREADS",
    ):
        os.environ[variable] = value


def seed_everything(seed: int) -> dict[str, Any]:
    random.seed(seed)
    seeded: dict[str, Any] = {"python_random": True}

    if importlib.util.find_spec("numpy") is not None:
        import numpy as np

        np.random.seed(seed)
        seeded["numpy"] = True
    else:
        seeded["numpy"] = False

    if importlib.util.find_spec("torch") is not None:
        import torch

        torch.manual_seed(seed)
        if torch.cuda.is_available():
            torch.cuda.manual_seed_all(seed)
        seeded["torch"] = True
    else:
        seeded["torch"] = False

    return seeded
```

M0 không cần cài NumPy/PyTorch chỉ để smoke. Helper hỗ trợ chúng khi dependency
groups tương ứng được cài ở milestone sau.

`PYTHONHASHSEED` không có hiệu lực đầy đủ nếu chỉ set sau khi Python process đã
khởi động. Training launcher sau này phải truyền nó trước khi start process:

```bash
PYTHONHASHSEED=42 uv run fraudguard train ...
```

Không tuyên bố “deterministic tuyệt đối”. Seed chỉ là một phần; GPU kernels,
thread scheduling và library versions vẫn có thể gây khác biệt.

### 6.2 Thứ tự import

Thread-limit environment variables phải được cấu hình trước khi import NumPy,
scikit-learn, LightGBM, XGBoost hoặc PyTorch. Vì vậy:

1. CLI parse typed config.
2. Configure thread limits.
3. Seed libraries.
4. Sau đó mới import module training/model nặng.

Không đặt heavy imports ở đầu `cli.py`.

## 7. Bước 4 — Runtime metadata

### 7.1 Schema

`ml/src/fraudguard_ml/runtime.py` nên có immutable model:

```python
from __future__ import annotations

from pydantic import BaseModel, ConfigDict


class GpuDevice(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    index: int
    name: str
    memory_total_bytes: int | None


class RuntimeMetadata(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    random_seed: int
    python_version: str
    platform: str
    cpu_logical_count: int
    cpu_available_count: int
    cpu_thread_limit: int
    host_memory_total_bytes: int
    host_memory_available_bytes: int
    configured_memory_limit_bytes: int
    gpu_available: bool
    gpu_backend: str | None
    gpu_devices: tuple[GpuDevice, ...]
```

Không dùng `"RTX 3050"` hoặc số CPU hard-code. Metadata phải được đo tại runtime.

### 7.2 CPU detection

Python 3.12 chưa có `os.process_cpu_count()`. Dùng affinity trên Linux và
fallback:

```python
import os


def available_cpu_count() -> int:
    if hasattr(os, "sched_getaffinity"):
        return len(os.sched_getaffinity(0))
    return os.cpu_count() or 1
```

Ghi cả:

- `cpu_logical_count`: CPU host nhìn thấy;
- `cpu_available_count`: CPU process được phép dùng;
- `cpu_thread_limit`: limit từ typed config.

Training code sử dụng:

```python
effective_threads = min(
    metadata.cpu_available_count,
    metadata.cpu_thread_limit,
)
```

### 7.3 RAM detection

Đoạn code này phải được viết trong file
`ml/src/fraudguard_ml/runtime.py`, bên trong hàm
`collect_runtime_metadata()`. Không đặt `memory = psutil.virtual_memory()` ở
cấp module vì khi đó phép đo sẽ chạy ngay lúc import và chưa có `config`.

Ví dụ vị trí triển khai:

```python
from __future__ import annotations

import os
import platform
import sys

import psutil

from fraudguard_ml.config import RuntimeConfig


def collect_runtime_metadata(
    config: RuntimeConfig,
) -> RuntimeMetadata:
    memory = psutil.virtual_memory()

    host_memory_total_bytes = int(memory.total)
    host_memory_available_bytes = int(memory.available)
    configured_memory_limit_bytes = int(
        config.memory_limit_gib * 1024**3
    )

    return RuntimeMetadata(
        random_seed=config.random_seed,
        # Các field CPU/platform được thu thập trong cùng hàm.
        cpu_logical_count=os.cpu_count() or 1,
        cpu_available_count=available_cpu_count(),
        cpu_thread_limit=config.max_cpu_threads,
        host_memory_total_bytes=host_memory_total_bytes,
        host_memory_available_bytes=host_memory_available_bytes,
        configured_memory_limit_bytes=configured_memory_limit_bytes,
        # Các field GPU được điền bởi GPU detector ở mục 7.4.
        gpu_available=False,
        gpu_backend=None,
        gpu_devices=(),
        # Điền python_version và platform theo schema ở mục 7.1.
        python_version=sys.version,
        platform=platform.platform(),
    )
```

Đoạn rút gọn dưới đây chỉ minh họa phép tính, không phải code đặt trực tiếp ở
đầu file:

```python
import psutil

memory = psutil.virtual_memory()
host_memory_total_bytes = int(memory.total)
host_memory_available_bytes = int(memory.available)
configured_memory_limit_bytes = int(
    config.memory_limit_gib * 1024**3
)
```

`config` trong đoạn trên là `RuntimeConfig` được truyền từ `cli.py` hoặc training
runner:

```python
runtime_metadata = collect_runtime_metadata(config.runtime)
```

Policy validation:

- config limit không được lớn hơn detected total memory;
- smoke chỉ warning nếu current available memory thấp hơn limit;
- training runner phải fail sớm hoặc giảm workload nếu không đạt minimum memory.

Không dùng `free -h` parsing trong Python package.

### 7.4 GPU detection

GPU detection phải optional và không làm import package thất bại.

Ưu tiên:

1. Nếu PyTorch đã cài: dùng `torch.cuda.is_available()` và device properties.
2. Nếu chưa có PyTorch: có thể dùng `nvidia-smi` để ghi hardware visibility,
   nhưng phải phân biệt với “PyTorch CUDA usable”.
3. Nếu không có cả hai: trả `gpu_available=False`, không raise trừ khi
   `require_gpu=true`.

Metadata nên dùng `gpu_backend`:

- `"torch-cuda"`: training thực sự dùng được CUDA;
- `"nvidia-smi-only"`: thấy GPU nhưng training backend chưa được xác nhận;
- `None`: không thấy GPU.

Không đánh đồng `nvidia-smi` chạy được với PyTorch CUDA tương thích.

### 7.5 Collector contract

```python
def collect_runtime_metadata(
    config: RuntimeConfig,
) -> RuntimeMetadata:
    ...
```

Function phải:

- không kết nối network/service;
- không ghi file;
- trả typed model;
- degrade gracefully khi GPU tooling không có;
- fail rõ ràng nếu `require_gpu=true` nhưng CUDA backend không dùng được.

### 7.6 Gắn vào mọi training run

Mọi training entry point sau này phải bắt đầu bằng cùng contract:

```python
config = load_yaml_config(config_path, TrainingConfig)
configure_thread_limits(config.runtime.max_cpu_threads)
seed_status = seed_everything(config.runtime.random_seed)
runtime = collect_runtime_metadata(config.runtime)

with start_tracked_run(config=config) as run:
    run.log_runtime(runtime)
    run.log_seed_status(seed_status)
    train(config)
```

Trong M0 chưa có MLflow, smoke command in runtime JSON. Đến M5, tracking adapter
phải log exact JSON này làm artifact `runtime.json` và flatten các field quan
trọng thành MLflow params/tags.

Không cho phép mỗi model tự viết logic CPU/GPU/seed riêng.

## 8. Bước 5 — CLI và service-free smoke command

### 8.1 CLI contract

M0 dùng `argparse` từ standard library; chưa cần thêm Typer/Click.

```text
fraudguard
└── smoke
    ├── --config PATH     required
    └── --json            machine-readable output
```

`ml/src/fraudguard_ml/cli.py` skeleton:

```python
from __future__ import annotations

import argparse
import json
from pathlib import Path
from typing import Sequence

from pydantic import ValidationError

from fraudguard_ml.config import SmokeConfig, load_yaml_config
from fraudguard_ml.reproducibility import (
    configure_thread_limits,
    seed_everything,
)
from fraudguard_ml.runtime import collect_runtime_metadata


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="fraudguard")
    subparsers = parser.add_subparsers(dest="command", required=True)

    smoke = subparsers.add_parser(
        "smoke",
        help="Validate package, config, seed and local runtime.",
    )
    smoke.add_argument(
        "--config",
        type=Path,
        required=True,
    )
    smoke.add_argument(
        "--json",
        action="store_true",
        dest="json_output",
    )
    return parser


def run_smoke(config_path: Path, json_output: bool) -> int:
    config = load_yaml_config(config_path, SmokeConfig)
    configure_thread_limits(config.runtime.max_cpu_threads)
    seed_status = seed_everything(config.runtime.random_seed)
    runtime = collect_runtime_metadata(config.runtime)

    result = {
        "status": "ok",
        "config": config.model_dump(mode="json"),
        "seed_status": seed_status,
        "runtime": runtime.model_dump(mode="json"),
    }

    if json_output:
        print(json.dumps(result, indent=2, sort_keys=True))
    else:
        print(
            "FraudGuard smoke check passed: "
            f"cpus={runtime.cpu_available_count}, "
            f"gpu={runtime.gpu_available}, "
            f"seed={runtime.random_seed}"
        )
    return 0


def main(argv: Sequence[str] | None = None) -> None:
    parser = build_parser()
    args = parser.parse_args(argv)

    try:
        if args.command == "smoke":
            exit_code = run_smoke(args.config, args.json_output)
        else:
            parser.error(f"Unknown command: {args.command}")
    except (OSError, ValueError, ValidationError) as exc:
        parser.exit(2, f"configuration error: {exc}\n")

    raise SystemExit(exit_code)
```

Khi implement, tránh `except Exception`: lỗi lập trình không được ngụy trang
thành config error.

### 8.2 Smoke invariants

Smoke command không được:

- import Kafka producer;
- gọi Docker CLI;
- ping database/object store;
- đọc `.env`;
- đọc `data/data.csv`;
- import ML libraries nặng nếu chưa cài;
- thay đổi random config;
- ghi runtime artifact vào Git workspace.

Integration health checks thuộc milestone/test suite khác.

## 10. Bước 7 — Tests cần viết trước khi coi M0 hoàn thành

### 10.1 Config tests

`ml/tests/test_config.py` phải cover:

- valid YAML;
- missing config file;
- malformed YAML;
- YAML root là list/scalar/null;
- unknown field;
- missing `runtime`;
- negative/out-of-range seed;
- string thay cho integer khi strict mode;
- zero/negative CPU hoặc memory limit;
- loaded config immutable.

Ví dụ:

```python
from pathlib import Path

import pytest
from pydantic import ValidationError

from fraudguard_ml.config import SmokeConfig, load_yaml_config


def test_config_rejects_unknown_fields(tmp_path: Path) -> None:
    config_path = tmp_path / "smoke.yaml"
    config_path.write_text(
        """
schema_version: 1
project_name: fraudguard
runtime:
  random_seed: 42
  max_cpu_threads: 8
  memory_limit_gib: 6.0
  require_gpu: false
  random_sead: 7
""",
        encoding="utf-8",
    )

    with pytest.raises(ValidationError):
        load_yaml_config(config_path, SmokeConfig)
```

### 10.2 Runtime tests

Không assert máy CI có đúng 16 CPU hoặc GPU:

```python
def test_runtime_metadata_has_valid_resource_values(
    smoke_config: SmokeConfig,
) -> None:
    metadata = collect_runtime_metadata(smoke_config.runtime)

    assert metadata.random_seed == 42
    assert metadata.cpu_logical_count >= 1
    assert metadata.cpu_available_count >= 1
    assert metadata.cpu_thread_limit == 8
    assert metadata.host_memory_total_bytes > 0
    assert metadata.host_memory_available_bytes > 0
    assert metadata.configured_memory_limit_bytes == 6 * 1024**3
```

GPU branches phải test bằng monkeypatch/fake detector, không phụ thuộc hardware
thật của test runner.

### 10.3 Seed tests

- Cùng seed tạo cùng Python random sequence.
- Khác seed tạo sequence khác.
- Missing optional NumPy/PyTorch không làm helper fail.
- Thread-limit variables nhận đúng giá trị.

### 10.4 CLI tests

Chạy CLI như installed module:

```python
import json
import subprocess
import sys


def test_smoke_cli_returns_json() -> None:
    completed = subprocess.run(
        [
            sys.executable,
            "-m",
            "fraudguard_ml",
            "smoke",
            "--config",
            "configs/smoke.yaml",
            "--json",
        ],
        check=False,
        capture_output=True,
        text=True,
    )

    assert completed.returncode == 0, completed.stderr
    payload = json.loads(completed.stdout)
    assert payload["status"] == "ok"
    assert payload["runtime"]["random_seed"] == 42
```

Thêm test invalid config trả exit code `2` và message không chứa traceback.

## 11. Bước 8 — pre-commit

Để `uv.lock` là nguồn version duy nhất, dùng local hooks chạy tool từ project
environment:

`.pre-commit-config.yaml`:

```yaml
repos:
  - repo: local
    hooks:
      - id: ruff-check
        name: ruff check
        entry: uv run ruff check --fix
        language: system
        types: [python]

      - id: ruff-format
        name: ruff format
        entry: uv run ruff format --check
        language: system
        types: [python]

      - id: mypy
        name: mypy
        entry: uv run mypy ml/src/fraudguard_ml ml/tests
        language: system
        pass_filenames: false
        types: [python]

      - id: pytest-smoke
        name: pytest smoke
        entry: uv run pytest -m smoke
        language: system
        pass_filenames: false
        types: [python]
```

Sau khi tạo:

```bash
uv run pre-commit install
uv run pre-commit run --all-files
```

Không đưa full integration tests vào pre-commit; commit phải nhanh và không cần
services.

## 12. Thứ tự code được khuyến nghị

Không code tất cả rồi mới test. Dùng các vertical slices:

### Slice 1 — Package import

1. Thêm build system và setuptools package discovery.
2. Tạo `__init__.py`, `__main__.py`, CLI `--help`.
3. Chạy `uv sync`, `uv build`, import và help.

### Slice 2 — Typed config

1. Thêm direct Pydantic/PyYAML dependencies.
2. Tạo strict models và loader.
3. Tạo `configs/smoke.yaml`.
4. Viết config tests.

### Slice 3 — Runtime/reproducibility

1. Thêm psutil.
2. Implement CPU/RAM detector.
3. Implement optional GPU detector.
4. Implement seed/thread helpers.
5. Viết unit tests với monkeypatch.

### Slice 4 — Smoke CLI

1. Kết nối config, seed và runtime collector.
2. Thêm JSON/human output.
3. Viết CLI subprocess tests.

### Slice 5 — Quality gate

1. Thêm Ruff/mypy/pytest configs.
2. Sửa toàn bộ lỗi trong phạm vi M0.
3. Thêm pre-commit.
4. Chạy Definition of Done commands.

Mỗi slice nên là một commit độc lập nếu em muốn luyện Git history chuyên
nghiệp.

## 13. Các lỗi thiết kế cần tránh

- Coi package tồn tại vì `PYTHONPATH` trỏ thủ công vào source.
- Dùng `sys.path.append(...)` trong tests hoặc CLI.
- Tạo nested `pyproject.toml`, `.venv` hoặc `uv.lock` trong `ml/`.
- Dùng YAML dictionary xuyên suốt application.
- Cho Pydantic bỏ qua unknown fields.
- Import PyTorch để kiểm tra GPU ngay khi import package.
- Set seed riêng ở từng model.
- Log chỉ số CPU/GPU từ máy của developer thay vì đo ở run.
- Hard-code `16 CPU`, `8 GB RAM`, `RTX 3050`.
- Đánh đồng GPU nhìn thấy bởi `nvidia-smi` với CUDA usable.
- Bắt smoke test phụ thuộc Docker hoặc dataset.
- Bật quá nhiều lint rules rồi thêm ignore hàng loạt.
- Dùng `ignore_missing_imports = true` cho toàn bộ mypy.
- Cài tool bằng `uvx` trong pre-commit nhưng không khóa version cùng project.
